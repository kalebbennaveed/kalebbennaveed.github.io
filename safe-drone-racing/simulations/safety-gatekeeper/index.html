CURRENT IMPLEMENTATION

How the flight is generated

Base modelKnown equations for motion, orientation, thrust response and body-rate response.

Prediction modelBase model + a neural network's learned acceleration correction. Used to predict future states.

Ground-truth simulatorThe simulated drone that receives the applied commands. Scenarios 1 and 3 add drag and acceleration bias that are absent from the base model.

  1. MPPI generates the racing plan.

    It tries command sequences, predicts their motion with the prediction model, and scores forward progress, course error and control effort. Its output is a two-second sequence of reference states and thrust/body-rate commands.

  2. With Gatekeeper: simulate a candidate.

    Starting at the measured state, simulate the neural tracker following the MPPI racing plan until a chosen switch time. Then simulate the backup controller, which follows the course centerline at 2 m/s. The prediction model produces every future state. The first candidate has no racing segment: backup starts immediately.

  3. Check the candidate, then keep an accepted reference.

    Propagate model error and measurement error along the candidate, using Jacobians of the prediction model together with the neural feedback policy. Check the resulting position bounds against the course, then check position, velocity and tilt error at the end of the candidate. An accepted candidate becomes the trajectory to follow. If a later candidate fails, the previously accepted trajectory stays active, including its moving backup.

  4. The neural tracker generates applied commands.

    It receives the measured state, reference state/command and previous command. It outputs thrust and body rates, subject to magnitude and change-rate limits. It tracks the whole accepted reference, including the backup portion. The geometric backup generates that reference; it does not replace the executing neural tracker.

Startup: Base model + the declared bound on unknown drag and acceleration bias → simulate the moving backup immediately → verify → begin tracking. No preliminary data-collection flight is required. Dynamics learning and neural-controller adaptation then use measurements collected during flight.

Without Gatekeeper: MPPI reference → neural tracker → ground-truth simulator. No candidate check, acceptance decision or backup switch is used. These are Scenarios 2 and 3 below.

Dynamics learning and controller learning

The dynamics ensemble averages three networks to predict an acceleration correction from measured state changes and applied commands. The control-policy network learns how to track a reference. When the dynamics model changes, policy training simulates tracking with that model and updates the controller weights by backpropagation through time. No ATS is used. In a Gatekeeper run, a policy update enters execution only with an accepted candidate; without Gatekeeper, it enters after the training validation check.

Gatekeeper uses a local linear approximation (the Jacobian) to propagate uncertainty. A mathematical guarantee that these bounds contain every nonlinear motion, or that the moving backup remains safe indefinitely, has not been established. The force limit available at startup is an assumption about the possible drag and bias. It is not learned before measurements are collected. The ground-truth simulator is a 14-state body-rate/actuator model, not a rotor-resolved high-fidelity simulator.

    Move over a map to inspect a state.

    Each map changes only the two selected inputs. All remaining inputs use the same starting values in both maps. The colors are acceleration-error bounds, not position or velocity error.
